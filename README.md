# DATA SCIENCE PROJECT

## 1. Proposed project
**Project title:** Olist E-Commerce Business Intelligence & Predictive Analytics

**Business problem statement:**

How can an e-commerce business use historical order, customer, product, payment, seller, delivery and review data to understand its sales performance, identify factors associated with customer satisfaction and delivery delays, and predict future business outcomes to improve operational decisions?

## 2. Why are we using the Olist dataset?
The Olist Brazilian E-Commerce Dataset contains multiple connected tables covering orders, customers, products, sellers, payments, reviews, delivery timestamps and geography.

That makes it useful for practicing:
- Data cleaning across multiple related CSV files.
- SQL joins and relational database design.
- Statistical analysis and feature relationships.
- Historical business intelligence in Power BI.
- Machine learning using real transaction data.
- Predictive dashboards linked to SQL outputs.

One limitation: the dataset represents historical Brazilian e-commerce activity, primarily from 2016–2018. Our findings will describe that dataset and should not automatically be treated as representative of today's entire e-commerce market.

## 3. The plan we'll follow:

# Olist E-Commerce Data Science Project

## Project Workflow

1. **Data Ingestion** — Collect Olist CSV datasets.
2. **ETL & Data Cleaning** — Use Pandas and NumPy to inspect, clean, and transform data.
3. **Data Validation** — Check missing values, duplicates, data types, business rules, and table relationships.
4. **Statistics & EDA** — Analyze distributions, outliers, correlations, and business patterns.
5. **SQL Database** — Design tables and store cleaned data.
6. **Power BI 1** — Build historical sales and customer analytics dashboards.
7. **Feature Engineering** — Create meaningful features for machine learning.
8. **Machine Learning** — Train, compare, and tune suitable models.
9. **Model Evaluation** — Evaluate performance, compare with baselines, and select the best model.
10. **SQL Predictions Storage** — Store predictions, timestamps, and model version metadata.
11. **Power BI 2** — Visualize predictions, forecast accuracy, and business recommendations.
12. **Documentation** — Prepare the GitHub README, methodology, findings, evaluation metrics, limitations, and recommendations.
